# 2026-10-01

## 修复：首页新建笔记按钮（FAB）加号图标偏左歪斜

- 现象：列表页右下角悬浮按钮里的白色「+」不在圆心，明显偏左且偏小（H5 与小程序同源同病）
- 排查：playwright + 像素级分析（ASCII 渲染圆内墨迹），测得墨迹中心 (24, 28) vs 按钮中心 (27.5, 27.5)，且加号只有约 9px（按 26px 字号应为 15px）；字体数据用 fontTools 解析却显示墨迹完全居中 → 矛盾点锁定在字体文件本身
- 根因：lnicon.ttf 是 Remixicon 子集化产物，但子集化时 **hmtx 的 lsb 全部为 0，与各字形 glyf 头部的 xMin 不一致**（如 uniEA13 lsb=0 而 xMin=275）。Chrome 等渲染器按 lsb 定位字形，导致墨迹整体左移、观感变小。另外 iconfont.scss 内嵌的 base64 是**旧版字体，只有 13 个字形**（缺 check/edit/location/mail 4 个码点），与 static/fonts/lnicon.ttf（17 个全）不同步
- 修复：用 fontTools 把 17 个字形的 lsb 重算为各自 xMin 后回写 ttf，再从修复后的 ttf 重新生成 base64 替换 iconfont.scss 中的旧串
- 验证：H5 像素级复测加号墨迹中心 (27.5, 27.5) 与按钮中心完全重合、尺寸恢复 15px；`npm run build:mp-weixin` 编译通过。base64 两端共用，小程序端需重新编译后在开发者工具确认（未在真机验证）
- 教训：图标字体「看起来歪/小」先查 hmtx.lsb 与 glyf.xMin 是否一致，fontTools 正常读不代表渲染器正常渲染；scss 内嵌 base64 与 static 下 ttf 是两份拷贝，改字体必须两边同步
