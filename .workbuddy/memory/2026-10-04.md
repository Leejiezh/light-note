# 2026-10-04 分页对齐后端统一契约（docs/api/pagination.md）

## 背景

用户给出后端分页契约（`docs/api/pagination.md`）：所有分页接口统一 **请求 `pageNum` / `pageSize`**（GET 查询串）+ **响应 `PageResult` = `{ list, total, pageNum, pageSize, hasNext }`**，业务 VO（`RecordVO` / `ReportVO`）字段尚未冻结、本次不动。前端原来是自造的游标分页（`cursor` / `limit` / `hasMore`），与后端对不上。

## 改了什么

### 1. 类型（`src/api/types.ts`）

- 新增 `PageQuery { pageNum?, pageSize? }`
- `PageResult<V>` 从「游标」改写为契约形状：`list` / `total` / `pageNum` / `pageSize` / `hasNext`
- `NoteQuery` / `SearchQuery` 改为 `extends PageQuery`，删掉 `cursor` / `limit`
- `SearchResult` 由 `PageResult<SearchHit> & { total }` 简化为 `= PageResult<SearchHit>`（total 已在里面）
- `ApiEnvelope` 注解标注对应契约 `R<T>`（code / msg / data），字段本身未变，`client.ts` 的剥壳与 401 判定已符合契约（看 `body.code`，不看 HTTP 状态码）

### 2. 新增 `src/api/pagination.ts`

- `DEFAULT_PAGE_SIZE = 10`、`MAX_PAGE_SIZE = 100`、`normalizePageQuery()`
- 归一化：页码缺失/非法 → 1；每页缺失/非法 → 10，夹到 1 ~ 100
- ★ **只产出 `pageNum` / `pageSize` 两个字段**，避免 `undefined` 被拼进查询串

### 3. 领域接口与 mock

- `modules/note.ts` 的 `getNotes`、`modules/search.ts` 的 `search`：`pageNum` / `pageSize` 进 GET 查询串（uni.request 对 GET 会把 `data` 转成 query string，无需自己拼）；`tag` / `q` 只在有值时才带
- `mock/handler.ts` 新增 `paginate(all, query)` 统一切片，`/notes` 与 `/search` 都走它，响应形状与真实后端一致
- `index.ts` 出口补 `PageQuery` 类型与 `DEFAULT_PAGE_SIZE` / `MAX_PAGE_SIZE` / `normalizePageQuery`

### 4. 页面

- `list.vue`：补上拉加载（`onReachBottom` → 只有 `hasNext` 才请求下一页）；底部文案在「上拉加载更多 / 正在加载… / 共 N 条笔记」间切换；`共 N 条` 改用响应 `total`
- `search.vue`：同样分页 + 上拉加载，`fetchPage(page, append)` 区分「新搜索替换」与「上拉追加」；清空关键词时重置分页状态
- `mine.vue`：统计的 `total` 改用 `notesRes.total`（原来是当前页 `list.length`，接分页后会算错）

## 关键决策

- **页码按「目标页」请求，成功后才落库**（`targetPage = pageNum + 1`）：失败时 `pageNum` 不前进，下次上拉不会漏掉一页
- **不动端点**：后端的 `/record/page`、`/report/page` 只接受分页参数、无筛选字段，且 VO 未冻结 —— 本次只对齐「分页外壳」，`/notes`、`/search` 仍是前端自有端点，页面里的标签筛选不受影响
- **上拉加载属于契约的一部分**（文档 §3 明确 `if (hasNext) pageNum++`）：两个列表页都补了，否则 `pageSize` 会把列表静默截断

# 2026-10-04 标签字典改为「冷启动拉一次」（修 note_label 被反复请求）

## 背景

列表页点一次标签筛选就多打一次 `GET /dict/note_label`：`load()` 里调了 `ensureTagDict()`，而它是**并发去重**（`inflight` 在请求结束的 `finally` 里被清空），不是「加载过就不再拉」，所以切标签 / 下拉刷新 / onShow 返回列表页都会各发一次请求。

## 改了什么

- `src/utils/store/tags.ts`：新增 `loaded` 标记（会话级）。`fetchDict` 成功后置位（空数组也算成功，否则会退化成「每次 ensure 都重试」）；失败**不**置位，保留重试机会。`ensureTagDict` 开头 `if (loaded) return Promise.resolve();` —— 已加载就只读缓存，不再发请求
- `src/App.vue`：`onLaunch` 里 `ensureTagDict().catch(() => {})`（冷启动拉一次；onLaunch 只在冷启动触发，切后台回前台不重复拉，正是想要的语义）
- `src/pages/list/list.vue`：调用保留为兜底（冷启动成功 → 同步空转；失败 → 本页重试），只改注释
- `detail.vue` / `tags.vue` 不用改：`ensureTagDict()` 现在天然幂等
- 顺手修掉 `tags.ts` 里一个既有 lint error（`normalizeDict` 里多余的类型断言 + 随之不再使用的 `DictItemExtra` 导入）

## 测试

`tests/tags.test.ts` 原本**加载阶段就失败**（经 `src/api` 门面 → `request.ts` → `mock/handler.ts` → `@/utils/markdown`，而 `vitest.config.ts` 刻意不配 `@` 别名），不是本次改动引起，但挡住了这条套件。改法：

- 顶部用 `vi.hoisted` + `vi.mock('../src/api', ...)` 只替换 `getNoteLabels`，不加载传输层 —— 顺带让「接口被调了几次」成为可断言量
- 新用例：失败不锁定 → 重试发出第二次请求 → 成功后连调两次 `ensureTagDict` 调用次数仍为 2，并断言字典已更新且落缓存
- 反向验证过：把 `if (loaded) return` 改成永假，该用例变红（`expected 4 to be 2`），说明它真能抓回归

`npm test` 4 个文件全绿（parser 89 / profile 42 / tags 29 断言 / errorMessage 9）；`npm run type-check` / `npm run lint` 无 error。

## 权衡

后端改了标签（新增 / 改名 / 改色）后，需**杀掉小程序重进**（冷启动）才会生效 —— 换来的是筛选、翻页、返回列表都不再产生多余的字典请求。若日后要「不重启也能刷」，在「我的」页加手动刷新入口即可，不要把自动请求挂回页面生命周期。
