# 2026-10-02 全量迁移 Vue3 + TypeScript + 请求层分层重构

## 背景

用户觉得 JS 代码乱（尤其 `src/utils/request/index.js` 把 token、统一请求、响应解析、各模块接口全写在一个文件里），选择方案 C：全量迁移 TypeScript，并按后端分层思路重构请求层。

## 改了什么

### 1. TS 基建

- 新增 `tsconfig.json`（strict、Bundler 解析、`@/*` 别名）
- 新增 `src/env.d.ts`：`.vue` shim + **wx 全局类型补充**（`@dcloudio/types` 只声明了 uni，没有 wx；补充了 `chooseMedia` / `getSelectedTextRange` / `getFileSystemManager` 的子集声明）
- 新增 `vitest.config.ts`（独立配置，**不加载** `@dcloudio/vite-plugin-uni`，避免 uni 插件在 node 测试环境的副作用）
- devDependencies 新增 `typescript@5.6.3`、`vue-tsc@2.1.10`、`vitest@2.1.9`；依赖树验证仍收敛（vue 3.4.21 唯一、vue-router 4.5.1、无嵌套 vue）

### 2. markdown / profile 迁移（行为不变）

- `src/utils/markdown/` 7 个 .js → .ts，新增 `types.ts`（`Segment` 判别联合、`TodoItem`）
- 入参刻意用 `unknown` 而非 `string`：测试里有 `sanitizeLine(123)`、`imageMarkdown(null)` 这类脏输入断言，原 JS 的 `String(x == null ? '' : x)` 防御逻辑保留才有意义
- `src/utils/store/profile.js` → `profile.ts`（`Profile` 规范形态 / `ProfileDraft` 脏数据入参）

### 3. 测试迁移到 vitest（131 用例全绿）

- `tests/*.test.mjs` → `.ts`；**保留原有 eq/ok 自定义 harness**，整块包进一个 `it()`，结尾 `expect(fail).toBe(0)` —— 改动最小、可逐条 diff 核对
- `package.json`：`test` 脚本 → `vitest run`

### 4. 请求层拆分 → `src/api/`（核心诉求）

```
src/api/
  types.ts    DTO（Note / NoteListItem / PageResult / SearchHit / NoteDraft …）
  config.ts   USE_MOCK / BASE_URL / TIMEOUT
  client.ts   传输层：uni.request + 统一包装 { code, data, msg } 剥壳（不知道 token）
  auth.ts     鉴权层：token 存取、wx code 换 token、ensureLogin 并发锁
  request.ts  编排层：拼 Authorization → client → 401 时 auth 重登 → 重放一次
  modules/    领域接口：note.ts / tag.ts / search.ts
  mock/       db.ts（内存数据）+ handler.ts（路由）
  index.ts    统一出口（页面只 import '@/api'）
```

- 后端类比：client ≈ RestTemplate，auth ≈ 拦截器，modules ≈ Controller，types ≈ DTO
- 原来的 `_skipAuth` 内部参数被分层自然消除：登录直接走 client.send，天然不带 token、天然不 401 重试
- **顺手修了一个 bug**：mock 路由原来匹配 `/login`，但实际请求是 `/auth/login`，开关打开后登录必挂；已对齐为 `/auth/login`
- 删掉 `loginWithCode` 里的调试 `console.log`

### 5. 页面与组件 → `lang="ts"`

- 6 页面 + 4 组件全部 `defineProps<...>()` 类型化；**template 与 style 块字节不动**（编辑器的键盘/光标约定零改动）
- editor 的事件回调参数用 `any` + 注释说明（uni 端 `e.detail` 是 `{ value, cursor, height }`，与 DOM `Event` / `FocusEvent` 类型不兼容，vue-tsc 会拦）

## 遇到的坑

- **npm 11 的 safe-delete（回收站机制）在 Windows 上有 bug**：装包时对旧文件的 `trash` 操作失败导致安装中断，`node_modules` 残缺（chai 半个目录）。修复：删掉残缺包目录后重装。以后遇到 `SAFE_DELETE_BULK_CONFIRM_REQUIRED` / tar TAR_ENTRY_ERROR 就这么处理
- `env.d.ts` 里写了 `export {}` 会让整个文件变成模块，`declare const wx` 就不再是全局 —— 全部页面报 `Cannot find name 'wx'`。删掉 `export {}` 即可
- uni.request 的 `data` 类型不接受 `null`：`options.data ?? undefined`

## 收尾清理

- 删除 `src/utils/markdown/package.json`（内容仅 `{"type":"module"}`）：原来给 `node tests/*.mjs` 直跑 ESM 用的，测试换 vitest 后已成死配置（且会给该目录下的 .js 强制 ESM 语义，留着是隐患）
- 全量扫描确认其余无残留：无 `.mjs`/`.cjs` 遗留、`src/utils/request/` 目录已整个移除、`src/**` 下无「无人 import 的死文件」
- **补迁漏掉的入口 `src/main.js` → `src/main.ts`**（第一轮只迁了页面/组件，漏了应用入口）。依据：`@dcloudio/uni-cli-shared/dist/resolve.js:32-44` 的 `resolveMainPathOnce` **优先探测 `main.ts`，不存在才回退 `main.js`**，H5 与小程序共用该解析器，因此改名是官方支持路径。改名后 `build:mp-weixin` 产物 `app.js` 仍含 `createApp` / `createSSRApp` / `ensureLogin`，入口链路未被切断
- 至此 `src/` 下已无任何 `.js` / `.mjs` / `.cjs` 文件

## 后续注意

- 改接口时：`modules/` 的函数签名、`mock/handler.ts` 的路由、`types.ts` 的 DTO **三处同步**
- `NoteDraft` 加了 `excerpt?: string` 便利字段（编辑器生成，后端可忽略）
- RUNNING.md 的「依赖版本不变式」验证清单未加 TS 工具链 —— 它们不触碰 vue 运行时，无需加入

## TS 化收尾优化（设计文档 2026-10-02-ts-optimization-design.md）

- 引入 ESLint flat config（`eslint.config.mjs`）：eslint + typescript-eslint + eslint-plugin-vue + @eslint/js + globals；`package.json` 加 `"lint": "eslint ."`。**文件名必须用 `.mjs`** —— package.json 没有 `"type": "module"`，`eslint.config.js` 会被按 CJS 解析，`import` 直接报错
- 新增 `tsconfig.node.json`：把根目录 `vite.config.ts` / `vitest.config.ts` 纳入类型检查工程（主 tsconfig 只管 src/tests），供 ESLint 类型感知规则使用
- `vite.config.js` → `vite.config.ts`（内容不变）；`mockApi` 改为泛型 `mockApi<T>()`，内部抽 `route()` 返回 `unknown`，`request.ts` 不再需要 `as T`
- 新增 `src/utils/errorMessage.ts`（`Error.message` → `errMsg` → fallback），替换 detail/list/mine(×2)/search/editor(×2) 共 7 处断言式提取，配 9 个单测
- `editor.vue` 消除两处 `any`：`UniTextareaInputEvent` / `UniTextareaFocusEvent`。**注意类型必须放宽才能过 vue-tsc**：模板按 DOM 签名校验（`@input` 的 payload 是 `Event`、`@focus` 是 `FocusEvent` 且其 `detail: number`），所以 input 事件要 `extends Event` + `detail?`，focus 事件 `detail` 写成 `number | { height?: number }`
- lint 规则取舍（均写在 config 注释里）：`no-floating-promises`/`no-misused-promises` 在 `src/pages/**` 关闭（uni.* 回调式 API 未传 success/fail 时返回 Promise，页面 fire-and-forget 是既定模式），保留在 api/utils/tests；`no-base-to-string` 在 markdown/store/mock 关闭（unknown→string 边界兜底）；纯排版 vue 规则关闭（项目不引入 Prettier）
- **顺手修掉一个环境级隐患**：`node_modules` 里有 698 个文件被改名成 `*.DELETE.<hash>`（此前某次 npm install 被中断的残局），导致 `@vitest/runner` 的 `.d.ts` 缺失、`describe/it` 退化成 any。因批量删除被环境钩子拦截，改为按后缀改名还原（317 个恢复），并 `npm install` 重建被删掉的 `node_modules/.bin`。**这也是此前 `vue-tsc` 报「零错误」有水分的部分原因（skipLibCheck 掩盖了 vitest 类型链断裂）**
- 验收：`npm run lint` 0 error / `npm test` 3 套件全绿 / `npm run type-check` 0 错误 / `npm run build:mp-weixin` 构建通过。编辑器事件类型改动**未在微信开发者工具与真机验证**
